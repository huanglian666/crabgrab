# CrabGrab 第四阶段：截图生成设计

## 目标

为 CrabGrab 增加 `sc` 子命令，从本地视频生成 PNG 截图。用户可以配置目标截图数量和必须使用的时间点；未被显式时间点占用的数量由程序随机补足。截图默认尝试烧录字幕，优先使用同目录、同基础名称且语言匹配的外挂字幕，其次回退到内封字幕，没有可用字幕时仍正常截图。

示例：

```bash
crabgrab sc -i "/path/Movie.mkv" -o "/path/output"
```

截图保存在 `/path/output/screenshots/`。

## 技术选择

采用独立 FFmpeg sidecar，通过 `std::process::Command` 调用，不把 FFmpeg 库链接到 Rust 程序。它沿用现有 MediaInfo sidecar 的版本固定、随软件分发和 SHA-256 校验模式。

首版优先降低开发、跨平台编译和维护复杂度，不制作极限裁剪的 FFmpeg 构建。安装包体积成为实际问题后，才单独裁剪不需要的协议、编码器和滤镜。程序不得回退调用 `PATH` 中未经校验的 FFmpeg。

## 命令与总体流程

CLI 新增：

```text
crabgrab sc -i <FILE> -o <DIRECTORY>
```

`-o` 表示资源的总输出目录，而不是截图目录。执行顺序如下：

1. 读取并验证通用配置及 `[screenshot]`。
2. 使用 MediaInfo 的结构化 JSON 输出读取视频时长、视频轨和字幕轨。
3. 解析显式时间点并随机补足目标数量。
4. 按语言优先级发现外挂字幕；没有时选择内封字幕。
5. 对每个时间点调用 FFmpeg，生成带字幕或无字幕的临时 PNG。
6. 全部成功后，将临时目录提交为 `<output>/screenshots/`。
7. 输出生成数量、目录、字幕来源和时间点摘要。

现有面向用户的 `mediainfo.txt` 流程保持不变。截图流程单独请求 MediaInfo JSON，不解析展示用文本报告。

## 模块边界

- `screenshot/config.rs`：截图配置验证和时间格式解析。
- `screenshot/timeline.rs`：固定时间点合并、随机补点、去重、间距和排序。
- `screenshot/subtitle.rs`：外挂字幕发现、语言排序和内封字幕轨选择。
- `screenshot/process.rs`：FFmpeg 定位、哈希验证、参数构造和进程执行。
- `screenshot/install.rs`：临时目录、所有权检查和事务式目录替换。
- `screenshot.rs`：编排完整截图流程并提供稳定接口。

CLI 对外使用短名称 `sc`，内部类型和模块保留完整的 `screenshot` 命名。

## 配置

配置模板增加：

```toml
[screenshot]
count = 3
timestamps = []
subtitles = true
subtitle_languages = ["zh-CN", "zh", "chs", "chi"]
```

字段定义：

- `count` 是目标截图总数，默认值为 3，有效范围为 `1..=100`。
- `timestamps` 是必须生成的时间点，支持 `HH:MM:SS`、`HH:MM:SS.mmm` 和百分比字符串，如 `65%`。
- `subtitles` 默认为 `true`；设为 `false` 时不发现也不渲染字幕。
- `subtitle_languages` 按顺序定义外挂字幕与内封字幕的语言偏好。匹配忽略大小写，并把语言标签中的 `_` 和 `-` 视为等价。

实际截图数量为：

```text
max(count, timestamps.length)
```

当显式时间点少于 `count` 时，程序随机补足差额；当显式时间点多于 `count` 时，保留全部显式时间点并提示实际数量已扩展。

当前配置加载逻辑需要解耦解析与 TMDB 验证。只有 TMDB 下载命令要求非空 API Token；`sc` 不依赖 TMDB 配置，`mediainfo` 独立命令仍无需读取配置。

## 时间轴计算

内部统一使用毫秒进行验证、比较和 FFmpeg 定位：

- 绝对时间必须小于视频总时长。
- 百分比必须严格位于 `0%..100%` 之间。
- 毫秒精度相同的显式时间点只生成一次，并向用户提示去重。
- 任一显式时间点无效时，整次任务在生成图片前失败。
- 最终时间点按时间升序排列，文件编号也按此顺序产生。

随机补点采用分区随机，而不是在完整时长内独立抽样：

1. 默认使用视频的 `5%..95%` 区间，降低命中片头和片尾的概率。
2. 根据待补数量将可用区间均分，在不同分区内分别随机取点。
3. 候选点应避开显式点和已经选择的随机点。
4. 非常短的视频自动缩小最小间距，优先保证可以生成目标数量。
5. 显式点占据某个分区时，从该分区剩余空间或其他剩余空间补点，避免紧邻截图。

每次执行允许产生不同随机点。首版不扫描黑帧或分析场景内容，避免额外解码整段视频。

## 字幕发现与选择

### 外挂字幕

首版支持 `.ass`、`.ssa`、`.srt` 和 `.vtt`。假设视频是 `Movie.2026.mkv`，候选名称包括：

```text
Movie.2026.zh-CN.ass
Movie.2026.zh_CN.srt
Movie.2026.zh.srt
Movie.2026.chs.ass
Movie.2026.chi.srt
Movie.2026.ass
Movie.2026.srt
```

选择顺序：

1. 按 `subtitle_languages` 顺序选择语言后缀。
2. 相同语言存在多个格式时，按 `ASS > SSA > SRT > VTT` 选择，以优先保留排版样式。
3. 没有语言匹配时，选择严格同基础名称且没有语言后缀的字幕，格式优先级相同。
4. 不将 `Movie-Trailer.srt`、`Movie.extra.srt` 等不明确名称视为匹配项。

### 内封字幕

没有外挂字幕时，使用 MediaInfo JSON 中的字幕轨信息：

1. 在标记为默认的可渲染轨中按语言偏好选择。
2. 没有默认轨时，在所有可渲染轨中按语言偏好选择。
3. 仍无语言命中时，选择第一条可渲染字幕轨。
4. 没有字幕轨时生成无字幕截图。

外挂字幕解析失败时先尝试内封字幕；内封字幕不可渲染时生成无字幕截图。字幕是增强能力，失败会产生警告但不会单独导致截图任务失败。首版不承诺支持外挂 `.sup` 等图形字幕；内封图形字幕由随包 FFmpeg 的实际能力决定。

## FFmpeg 执行边界

每个时间点启动一个 FFmpeg 进程，隔离单张截图的参数、输出和错误。代码通过 `Command::arg` 逐项传参，不通过 shell 拼接命令。

实现必须处理 FFmpeg 滤镜参数自身的路径转义，包括空格、中文、冒号、反斜杠和单引号。调用还需处理视频旋转元数据、非方形像素以及 PNG 兼容的 RGB/RGBA 像素格式。输入限定为本地文件，不启用网络协议。

FFmpeg stderr 必须有长度上限。视频无法定位、解码或输出有效图片属于任务失败；字幕滤镜失败则按既定回退链重试。

## 输出和事务语义

输出布局：

```text
<output>/
└── screenshots/
    ├── .crabgrab-screenshots
    ├── 01.png
    ├── 02.png
    └── 03.png
```

图片使用无损 PNG，保持原视频画面分辨率。编号宽度根据总数量决定，至少为两位。

`.crabgrab-screenshots` 是 TOML 格式的所有权与结果清单。例如：

```toml
ffmpeg_version = "..."
video = "Movie.mkv"

[[images]]
file = "01.png"
timestamp = "00:10:30"
subtitle = "Movie.zh-CN.ass"
```

清单和命令摘要中的时间统一显示为 `HH:MM:SS`。小时允许超过 24；内部定位仍保留毫秒精度。无字幕图片省略 `subtitle` 字段。

目录更新规则：

- `screenshots` 不存在时创建。
- 空目录可以接管并写入所有权标记。
- 带有效 CrabGrab 所有权标记的目录可以整体更新。
- 非空且没有有效所有权标记的目录拒绝覆盖。

所有新文件先生成到输出目录同级的唯一临时目录。全部成功后才切换为 `screenshots`；失败时删除临时结果并保留旧目录。替换已有的 CrabGrab 目录时，先重命名为备份，提交新目录成功后再清理备份；提交失败必须尝试恢复原目录。

## 用户输出与错误处理

成功摘要包含：

```text
screenshots: /media/Movie/screenshots
generated: 5
subtitle: Movie.zh-CN.ass
timestamps: 00:10:00, 00:28:41, ...
```

找不到字幕、外挂字幕损坏或内封字幕无法渲染时输出警告并降级。以下情况返回失败状态：

- 配置无效。
- 输入不存在、不是普通文件或没有视频轨。
- 无法得到有效视频时长。
- 显式时间点越界或格式错误。
- FFmpeg 缺失、版本不可用或 SHA-256 不匹配。
- 任一目标帧在无字幕模式下仍无法解码。
- 输出目录无法安全提交或恢复。

## 测试策略

单元测试覆盖：

- 配置默认值、数量边界和时间格式。
- 显式时间点少于、等于和多于 `count`。
- 时间点去重、排序、首尾边界、分区随机和短视频。
- 语言标签大小写、连字符和下划线归一化。
- 多语言、多格式外挂字幕的选择顺序。
- 外挂、内封默认轨、内封语言轨、第一可用轨和无字幕的完整回退链。
- FFmpeg 滤镜路径转义和进程参数构造。
- 字幕渲染失败后的重试和降级。
- 所有权标记检查、非所有目录保护、事务提交和失败恢复。

CLI 测试使用可注入的伪 MediaInfo/FFmpeg 执行器验证调度、参数和输出，不让常规测试依赖真实媒体工具。

端到端媒体夹具覆盖无字幕、外挂 SRT、外挂 ASS、内封文本字幕，以及随包构建支持时的内封图形字幕。端到端测试与普通快速测试分组，避免增加日常测试压力。

## 明确不在首版范围内

- 黑帧检测、镜头分析或内容质量评分。
- JPEG、WebP、缩放尺寸和图片质量配置。
- 同时烧录双语字幕或手动选择具体字幕轨。
- 外挂图形字幕的兼容性承诺。
- 并行启动多个 FFmpeg 进程。
- 直接链接 FFmpeg 动态库或维护平台原生解码实现。
