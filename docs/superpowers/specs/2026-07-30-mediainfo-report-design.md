# CrabGrab MediaInfo 报告设计

## 阶段目标

为 CrabGrab 增加独立的 MediaInfo 报告能力。用户提供一个本地媒体文件和输出目录，程序使用静态链接的 MediaInfoLib 分析文件，并在输出目录中生成 `mediainfo.txt`。

最终用户只需安装或下载 CrabGrab，不需要另外安装 MediaInfo、配置 `PATH`，也不需要随程序放置 `mediainfo.exe`、动态库或其他运行时组件。

本阶段正式支持：

- Windows x86_64，Rust 目标为 `x86_64-pc-windows-msvc`。
- macOS Apple Silicon，Rust 目标为 `aarch64-apple-darwin`。

Linux 是后续兼容目标。本阶段保持平台边界可扩展，但不发布或承诺 Linux 构建产物。

## CLI 设计

短参数形式：

```bash
crabgrab mediainfo -i <媒体文件> -o <输出目录>
```

完整参数形式：

```bash
crabgrab mediainfo --input <媒体文件> --output <输出目录>
```

行为约束：

- `mediainfo` 是独立子命令。
- `-i` 是 `--input` 的短参数，表示单个本地媒体文件。
- `-o` 是 `--output` 的短参数，表示输出目录。
- 两个参数都必须提供，每次只分析一个文件。
- 子命令不会读取 TMDB 配置、发起网络请求、下载图片或修改 `background` 和 `cover`。
- 现有顶层 `-i/--id`、`-o/--output` TMDB 图片下载行为保持不变。
- 现有版本、帮助和 `config` 子命令行为保持不变。

成功后向标准输出打印最终报告路径：

```text
mediainfo: <输出目录>/mediainfo.txt
```

错误和诊断信息写入标准错误，进程以非零状态退出。

## 输入与输出约定

输入只按文件系统属性验证：

- 路径必须存在。
- 路径必须指向可读取的普通文件。
- 不根据扩展名维护视频格式白名单。
- 文件类型和内容是否可识别交由 MediaInfoLib 判断。

需要时自动创建输出目录。输出目录存在时必须是目录。

最终目录可与现有图片输出共存：

```text
<输出目录>/
├── background/
│   └── background.jpg
├── cover/
│   └── cover.jpg
└── mediainfo.txt
```

MediaInfo 子命令只负责 `mediainfo.txt`。图片目录并非本子命令的前置条件，也不会由本子命令创建。

## 报告格式

报告直接使用 MediaInfoLib 的标准预格式化文本视图，不由 CrabGrab 筛选字段或重新排版。

- 使用标准详细程度，不启用 `Complete` 调试模式。
- 字段名称固定为英文，不跟随操作系统语言。
- 保留 `General`、`Video`、`Audio`、`Text` 等实际存在的分区。
- 保留 `Complete name`，其中包含 MediaInfoLib 报告的输入文件路径。
- 保留文件内嵌的厂商字段和自定义元数据。
- 输出编码固定为 UTF-8。
- CrabGrab 将换行规范化为 `LF`，并确保文件末尾恰好有一个换行，使两个正式支持平台的文件表现稳定。
- 不保证不同 MediaInfoLib 版本的报告逐字一致；CrabGrab 固定上游版本，使同一 CrabGrab 版本的行为可复现。

如果 MediaInfoLib 无法打开文件、返回空报告，或报告中没有 `Video`、`Audio`、`Text` 或其他非 `General` 媒体流，则操作失败且不生成新的正式报告。

## 架构与职责

建议新增以下边界：

```text
src/
├── cli.rs
├── media_info.rs
└── media_info/
    └── native.rs

native/
├── mediainfo_bridge.h
├── mediainfo_bridge.cpp
└── CMakeLists.txt

vendor/
├── MediaInfoLib/
└── ZenLib/
```

职责划分：

- `cli.rs`：定义 `mediainfo` 子命令并分派请求。
- `media_info.rs`：验证输入、创建输出目录、协调分析和事务式写入，并定义统一错误类型。
- `media_info/native.rs`：将原生接口包装为安全 Rust API。项目中与本功能有关的 `unsafe` 代码只允许出现在该模块，并为每个不安全假设写明约束。
- `mediainfo_bridge.h/.cpp`：将稳定的 C ABI 暴露给 Rust，转换平台路径，调用 MediaInfoLib，捕获 C++ 异常并管理跨边界内存。
- MediaInfoLib 与 ZenLib：固定版本的上游原生依赖，静态链接进最终 CrabGrab 可执行文件。

Rust 负责 CLI、文件系统操作、错误展示和输出事务。C++ 桥接层只负责原生库适配，不承担业务流程。

## 原生桥接边界

桥接层暴露窄而稳定的 C ABI：

- Windows 入口接收 Rust `OsStr` 编码得到的 UTF-16 代码单元指针和明确长度，不使用以 NUL 结尾的窄字符串。桥接层将其交给 MediaInfoLib 的宽字符路径接口，必须支持中文、空格和其他非 ASCII 路径。
- macOS 入口接收 Rust 路径的原生字节指针和明确长度，并在桥接层构造 MediaInfoLib 接受的路径值。
- 两个平台入口均返回同一种结果结构：稳定的状态码、报告指针与长度、错误指针与长度。成功时只设置报告，失败时只设置错误；未使用的指针必须为空且长度为零。
- 结果结构由桥接层分配，并由一个配对的桥接层释放函数统一释放。Rust 不单独释放结构中的字段。
- 输入和输出均通过指针加长度传递，不依赖 NUL 终止符或隐式全局状态。
- 成功返回 UTF-8 报告；失败返回 UTF-8 错误描述和稳定的结果状态。
- 分配与释放不得跨越不同运行库。
- 所有 C++ 异常，包括未知异常，都必须在桥接层捕获；异常不得越过 C ABI 边界。
- 空指针、无效长度、分配失败和字符串转换失败均返回受控错误。
- Rust 包装层验证返回状态、指针、长度和 UTF-8，再构造安全的 Rust 类型。

MediaInfoLib 配置为英文标准文本视图。网络分析、GUI、HTTP、图形插件和其他本阶段不需要的可选能力在构建时关闭。

## 数据流

一次成功执行按以下顺序进行：

1. clap 解析 `mediainfo` 子命令及两个必需参数。
2. Rust 验证输入是可读取的普通文件。
3. Rust 验证或创建输出目录。
4. Rust 安全包装层调用原生桥接接口。
5. 桥接层转换路径，并通过 MediaInfoLib 打开和分析文件。
6. 桥接层取得英文标准文本报告，将其作为 UTF-8 数据返回 Rust。
7. Rust 验证报告非空且包含可识别的媒体流，并规范化换行。
8. Rust 将完整报告写入输出目录内本次操作专用的临时文件。
9. 写入和刷新成功后，Rust 安全替换正式的 `mediainfo.txt`。
10. Rust 打印最终绝对路径。

整个流程不访问网络。

## 安全覆盖与并发

`mediainfo.txt` 已存在时默认安全覆盖：

1. 完整报告生成前不接触正式文件。
2. 在输出目录内创建名称不可预测且仅属于本次操作的临时文件，保证临时文件与正式文件位于同一文件系统。
3. 完整写入并刷新临时文件。
4. 如果正式文件存在，将其移动到本次操作专用的备份路径。
5. 将临时文件重命名为 `mediainfo.txt`。
6. 成功后删除备份。
7. 任一替换步骤失败时，尽最大可能恢复旧文件并清理本次临时文件。

不同进程并发写入同一输出目录时，不保证先后顺序。每个进程必须使用独立临时文件和备份名称，不能暴露半写入的正式文件，也不能清理无法确认属于本次操作的文件。

普通文件系统不能保证备份、替换和清理构成跨多个操作的完全原子事务。本设计保证分析或临时写入失败不会触碰旧文件，并通过备份与回滚降低替换阶段失败造成数据丢失的风险。

## 错误处理

错误应说明失败阶段和相关路径，但不得输出媒体文件内容。

输入和输出错误：

- 输入不存在：报告输入路径。
- 输入不是普通文件：提示提供媒体文件。
- 输入无法读取：报告路径和系统错误。
- 输出路径存在但不是目录：拒绝执行。
- 输出目录无法创建：报告目录和系统错误。

分析和桥接错误：

- MediaInfoLib 无法打开文件：提示文件不可读、被占用或格式不受支持。
- 报告为空或没有可识别媒体流：提示未识别出有效媒体信息。
- 平台路径转换失败：明确报告转换阶段。
- 内存分配失败或 C++ 异常：转换为受控原生桥接错误。
- Rust 收到无效指针、无效长度或非 UTF-8 内容：报告原生桥接协议错误，不继续使用该数据。

写入和替换错误：

- 临时文件创建、写入或刷新失败：报告临时写入阶段，并保留旧文件。
- 备份、重命名或恢复失败：报告对应路径和操作。
- 如果回滚也失败，错误必须同时说明原始替换错误与回滚错误，避免掩盖正式文件状态。

## 构建与依赖管理

- MediaInfoLib 和 ZenLib 使用锁定到明确提交的 Git submodule 管理。
- 构建不解析或下载浮动的“最新版”依赖。
- Cargo 是开发和构建的统一入口。
- `build.rs` 协调 CMake 构建桥接层、MediaInfoLib 和 ZenLib，并将静态库链接进 CrabGrab。
- Windows 使用 MSVC 工具链；macOS 使用 Apple Clang。
- 发布构建不得依赖目标机器已经安装 MediaInfoLib。
- 发布包附带 MediaInfoLib、ZenLib 及启用的第三方组件所要求的许可证和版权声明。

首次克隆源码的开发者需要递归初始化 submodule。这是源码构建要求，不是最终用户的运行时要求。

Linux 后续通过增加原生构建目标和 GitHub Actions 矩阵项支持。届时单独决定 glibc 最低版本或 musl 策略；本阶段不提前承诺 Linux ABI 范围。

## 测试策略

### CLI 解析与回归

- 接受 `mediainfo -i/-o` 和 `mediainfo --input/--output`。
- 缺少任一参数时非零退出并给出 clap 错误。
- MediaInfo 子命令不会触发配置读取或 TMDB 网络流程。
- 现有版本、帮助、配置和 TMDB 图片下载测试继续通过。

### Rust 流程单元测试

定义可注入的 `MediaAnalyzer` 边界，用假的分析器隔离原生库：

- 输入不存在、输入为目录和输入不可读取时失败。
- 不根据文件扩展名拒绝输入。
- 输出目录不存在时自动创建。
- 分析成功时生成 UTF-8 `mediainfo.txt`。
- 换行被规范化，文件末尾恰好有一个换行。
- 旧报告被完整安全替换。
- 分析、写入或替换失败时旧报告保持不变或被回滚。
- 成功和失败路径均清理本次临时文件与备份。

### 原生桥接集成测试

仓库保存一个体积小、来源和许可证明确的固定媒体样本：

- MediaInfoLib 可以打开样本并返回有效 UTF-8。
- 报告包含 `General`、`Video` 及样本实际拥有的其他分区。
- 核心字段为英文。
- 将样本复制到包含中文和空格的临时路径后仍能分析。
- 空文件和非媒体文件返回受控错误。
- C++ 异常或协议错误不能导致异常跨边界或未定义行为。

不对含绝对路径的整份报告做未经规范化的逐字 golden 比较。测试固定核心结构和字段；需要比较完整报告时，先替换平台相关路径并规范化换行。

### GitHub Actions 与发布验证

Windows x86_64 和 macOS arm64 均执行：

```text
cargo fmt --check
cargo clippy
cargo test
cargo build --release
原生静态链接检查
CLI 冒烟测试
```

发布工作流分别生成带操作系统和架构标识的压缩包及校验值。发布验证必须确认产物在未安装 MediaInfo 的干净环境中可以生成报告。

## 明确不做

本阶段不实现：

- 要求或探测系统安装的 `mediainfo` 命令。
- 随程序分发独立的 `mediainfo` 可执行文件或共享库。
- 多文件或目录批量扫描。
- 报告字段筛选、自定义模板、JSON、XML、HTML 或 CSV 输出。
- 报告本地化或 `--language` 参数。
- MediaInfo `Complete` 调试模式。
- 根据文件扩展名维护格式白名单。
- 修改、转码、修复或上传媒体文件。
- Linux 发布产物、Linux ABI 承诺或服务器部署方案。
- 本阶段业务以外的 CLI 重构、TMDB 改造、README、安装器或完整发布流水线实现。

## 完成标准

- `crabgrab mediainfo -i <媒体文件> -o <输出目录>` 可在正式支持平台生成 `mediainfo.txt`。
- 报告来自静态链接的 MediaInfoLib，并采用固定英文的标准文本视图。
- 最终用户无需安装 MediaInfo 或任何 MediaInfo 动态库。
- Windows x86_64 和 macOS arm64 均能处理中文及空格路径。
- 输出目录自动创建，已有报告默认安全覆盖。
- 分析或临时写入失败不破坏旧报告，替换失败执行回滚并报告状态。
- Rust 原生包装层提供安全接口，C++ 异常和跨边界内存得到正确处理。
- MediaInfoLib 和 ZenLib 版本固定，发布包满足其许可证声明要求。
- 自动化测试覆盖 CLI、Rust 流程、原生桥接、文件事务和现有功能回归。
- Windows x86_64 与 macOS arm64 构建、格式、静态检查、测试和冒烟验证全部通过。
- 没有实现本阶段明确排除的功能。
